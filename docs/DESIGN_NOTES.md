# 设计说明 / DESIGN NOTES

本文档解释 ECHOFORM 的视觉与交互决策，以及“声音 → 建筑”映射背后的设计逻辑。它不是 API 文档；代码细节见 `src/lib/design.ts` 与 `src/three/`。

---

## 1. 设计命题

大多数“声音可视化”把时间轴上的频谱画成柱子或波形，观众看到的是**数据**，不是**空间**。ECHOFORM 的命题是：

> 如果声音是一份建筑任务书，它会要求什么样的空间？

因此我们不做“跟着音乐跳动的几何”，而是先得到一份**设计规格**（`DesignSpec`），再让建筑按这份规格逐层浇筑。建筑必须有：基座、拱、侧殿、柱列、环、梯、悬浮物、粒子、光。它们不是装饰，而是声音结构的空间化。

---

## 2. 三种艺术方向

### 水晶圣殿 · CRYSTAL SANCTUM
- **原型**：哥特中殿 + 现代玻璃美术馆。
- **材料**：苍白石、低铁玻璃、磨砂金属、暖白自发光。
- **光**：低照度环境，中央光核，冷色天光从高侧窗渗入。
- **声音对应**：低音形成厚拱与基座；高音形成针状尖顶与纵向光柱；长音让玻璃更透。
- **情绪**：安静、仪式感、缓慢。

### 未来机械 · NEO MACHINE
- **原型**：粒子对撞机 + 航天器装配厂。
- **材料**：石墨、拉丝铝、青色信号光、橙色警示光。
- **光**：硬质轮廓光，顶部条形灯，地面反射。
- **声音对应**：节奏密度驱动桁架与机械环；起音驱动模块重复；低频驱动基座质量。
- **情绪**：精确、冷峻、有速度。

### 流体有机 · FLUID ORGANIC
- **原型**：贝壳、骨、菌丝、膜结构。
- **材料**：骨质瓷、半透明膜、湿润高光。
- **光**：柔和的体积光，暖色核心，边缘冷色。
- **声音对应**：长音把拱拉成连续腔体；音高范围驱动悬挑；高频让膜更薄、粒子更多。
- **情绪**：呼吸、柔软、身体感。

三种方向共享**同一套结构逻辑与指纹**，但重写几何生成、材质、灯光与粒子。这样同一段声音在三种方向下是“同一座建筑的不同材料版本”，而不是三张随机图。

## 3. 声音 → 建筑：设计规则

| 声音维度 | 空间决策 | 设计理由 |
| --- | --- | --- |
| 基频中位数 | 整体高度、拱高 | 低音天然对应“厚重、贴近地面”；高音对应“向上、轻盈”。 |
| 低频能量 | 拱的深度与宽度、基座 | 低频是建筑的“重量”，需要结构上的厚度来承接。 |
| 高频能量 / 亮度 | 柱列数量、碎片、粒子 | 高频是“细节与光”，在空间里表现为细密的垂直线与悬浮微粒。 |
| 响度 / RMS | 尺度、半径、光核亮度 | 响度是“能量”，直接改变建筑的体量与光的强度。 |
| 节奏密度 / 起音 | 旋梯级数、模块数量、机械环 | 节奏是“重复与运动”，对应可计数的构件。 |
| 停顿 / 静默 | 空厅、侧殿间距、缺口 | 停顿是“负空间”，必须在建筑里留下真正的空。 |
| 乐句 | 侧殿数量、出生顺序 | 一个乐句是一个空间章节；侧殿按乐句依次点亮。 |
| 音色 / 温暖度 | 材料、透光、光色 | 音色是“质地”，对应石材、玻璃、金属、膜。 |
| 动态范围 | 光环层数、明暗对比 | 动态范围是“戏剧性”，对应光的层次。 |

### 反随机原则

- 所有抖动来自 `mulberry32(seed)`，种子由指纹、风格、中位音高派生。
- `Math.random()` 不参与设计；只可能用于非关键的视觉噪声，且不影响 `DesignSpec`。
- 建筑名称也从同一颗种子选择，因此分享链接能复现标题。
- 时间轴上的出生时间写入 `DesignSpec`，刷新或重放不会改变建筑。

## 4. 视觉系统

### 色彩
- 背景：近黑 `#070706`，不是纯黑，保留暗部层次。
- 主文本：暖白 `#efe9dc`，避免冷白在暗场的刺眼。
- 强调色：随风格变化（水晶暖金、机械青、有机珊瑚）。
- 材质色不直接等于 UI 色；UI 只取一个 accent，避免“界面比建筑还亮”。

### 字体
- 标题：Instrument Serif，衬线、窄、带古典比例。
- 界面：Manrope，几何无衬线，数字用 tabular。
- 中文：系统宋体 / Noto Serif CJK，保持与英文标题的“建筑出版物”气质。
- 字号层级：标题 26–33 px，面板标签 9.5–10 px，数据 11–13 px；移动端不放大面板，保持信息密度。

### 构图
- 建筑主体略偏左，右侧留给控制室；移动端把面板做成底部抽屉，建筑在上方 270 px 内仍可见。
- 画面四周有极细的框线与暗角，像建筑摄影的取景框，而不是游戏 HUD。
- 光核始终在建筑中心偏下，作为“声音的心脏”；即使没有建筑，它也保持呼吸。

### 动效
- 一切缓动使用 `cubic-bezier(0.22, 1, 0.36, 1)`，慢入慢出。
- 建筑出生不是“缩放出现”，而是从地面向上生长，拱肋按乐句顺序点亮。
- 镜头导览是 CatmullRom 曲线，速度随乐句变化；停顿处镜头也会慢下来。
- `prefers-reduced-motion` 下降低粒子速度与镜头缓动，不改变最终构图。

## 5. 体验节奏

| 阶段 | 时长 | 设计意图 |
| --- | --- | --- |
| 序幕 | 用户决定 | 留白，建立“画廊”而不是“工具”的第一印象。 |
| 合成 / 分析 | 2.4 s 最短 | 让分析成为一段可读的叙事，而不是闪一下的 loading。 |
| 浇筑 | 与音频等长 | 建筑随声音生长；用户可以中途拖动时间轴。 |
| 漫游 | 不限 | 三种镜头覆盖“看建筑 / 走进建筑 / 被镜头带着走”。 |
| 导出 | 5–60 s | 海报即时，影像接近实时；导出过程有明确进度。 |

## 6. 交互原则

1. **一个主行动**：首屏只有“开始说话 / 上传 / 示例”，不堆功能。
2. **控制室是第二层**：风格、材质、灯光、档案放在面板里，不遮挡建筑。
3. **镜头模式显式**：轨道 / 漫游 / 导览三个词，而不是图标猜谜。
4. **移动端不缩水**：保留三种镜头、时间轴、风格、导出；用抽屉与循环按钮替代桌面多按钮。
5. **失败可恢复**：麦克风失败时引导上传；导出失败给 toast；分享失败给参数文件。

## 7. 可访问性与性能的设计取舍

- 不以颜色作为唯一状态提示：按钮有文字、`aria-label`、图标形状。
- 面板打开时焦点可键盘到达；`Esc` 关闭模态。
- 阴影与辉光用 CSS/后处理，不额外增加几何。
- 建筑几何按风格合并，透明材质排序； bloom 半分辨率，保证 1080p 的余量。
- 移动端 DPR 上限 1.6，桌面 2.0；性能不足时只降一次，避免画面抖动。

---

## 8. 不做什么

- 不做“频谱柱森林”：柱子必须与拱、殿、梯形成建筑关系。
- 不做随机生成：同一段声音必须可复现。
- 不做纯粒子秀：粒子是材质与光的延伸，不是主体。
- 不做通用模板：三种风格是三套完整的建筑语言。
- 不把音频上传：隐私是产品承诺，不是设置项。
